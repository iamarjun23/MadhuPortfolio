# Retire the mono voice, crown a serif

madhu.edit should move to **two families plus a rationed mono**: **Newsreader** (variable serif with optical sizes) for display and editorial accents, **Hanken Grotesk** (quiet variable grotesque) for body, navigation, labels and UI, and **JetBrains Mono at a single static weight** reserved for timecode-style data only. The current stack has four families and inverts every rule that makes a site read as classic. Mono is its dominant voice: a fresh count of `src/` finds **106 `var(--f-mono)` references against 35 display and 27 body**. Space Grotesk plus JetBrains Mono is the textbook "developer tool" pairing. Instrument Serif is loaded and preloaded on every route while `--f-serif` is used nowhere. The recommended system follows the pattern used by the cinephile end of the film world: a literary serif for headlines over a neutral grotesque for everything else, as MUBI (Tiempos + Riforma) and Janus Films (Freight Text + Freight Neo) do. It also matches the restraint of top editorial houses, most of which run one or two families. The change is a `src/app/layout.tsx` swap plus a CSS pass that moves most mono rules to the body face. It needs no new dependency. The work is mostly in that CSS audit, not the font choice.

## The site currently speaks in monospace, which reads "dev tool", not "film"

Expert consensus caps a professional system at two families, with a third allowed only for a narrow job. Butterick puts it bluntly: **"Most documents can tolerate a second font. Few can tolerate a third."** He adds that mixing works only when "each font has a consistent role" ([Practical Typography: Mixing fonts](https://practicaltypography.com/mixing-fonts.html)). On monospace he is sharper still: **"In standard body text, there are no good reasons to use monospaced fonts. So don't."** He also notes that tabular alignment, the usual excuse for mono, is already provided by most proportional fonts' tabular figures ([Practical Typography: Monospaced fonts](https://practicaltypography.com/monospaced-fonts.html)). Designer practice agrees. Only **6 of Typewolf's 40 favourite portfolio sites for 2026** use a mono at all, always next to a proportional face, and none adds a third family except a mono or one accent display face ([Typewolf: Top 40 portfolio sites 2026](https://www.typewolf.com/portfolio-sites)).

The film world draws the same line. A24 declares NB International Mono **4 times against 52** for NB International ([a24films.com](https://a24films.com); [Fonts In Use: A24 website](https://fontsinuse.com/uses/53928/a24-website)). Lost Planet, Hank Corwin's editorial company, uses Monument Grotesk Mono once against 19 uses of the main grotesque ([lostplanet.com](https://www.lostplanet.com)). That puts mono at roughly 5–7% of declarations, used for metadata. madhu.edit sits near 63%. Among observed editor portfolios, the only heavy-mono example is an outlier, Gal Anafi, with 38 Roboto Mono declarations ([gal-anafi.com](https://www.gal-anafi.com)). Portfolio guidance limits mono to dates, roles, tools and tags ([The Crit: Typography for portfolios](https://thecrit.co/resources/typography-for-portfolios)). Fontfabric files retro-computer styles under a "Digital Narrative" trend ([Fontfabric: Top typography trends 2026](https://www.fontfabric.com/blog/top-typography-trends-for-2026/)). That makes mono-as-brand a period look, not a classic one.

For a video editor, mono has exactly one honest job: **SMPTE timecode, durations, frame rates and version or date stamps**, short fixed-width strings where column alignment is the point. Section labels, eyebrows, navigation, buttons, client names and captions should move to the body sans, set in uppercase with tracking. This is a judgement grounded in the practice above. No study measures mono legibility for short UI labels specifically, so the argument rests on tone and consistency rather than measured readability.

## Film's prestige brands pair a literary serif with a quiet grotesque

The film industry splits in two. Commercial editorial and post houses overwhelmingly run one proprietary grotesque. About 11 of roughly 14 houses with readable CSS lead with a sans: Rock Paper Scissors uses Forma DJR, Exile uses Lota Grotesque, and Arcade uses Aktiv Grotesk Extended ([rockpaperscissors.com](https://www.rockpaperscissors.com); [exileedit.com](https://www.exileedit.com); [arcadeedit.com](https://www.arcadeedit.com)). That look is premium-contemporary, not classic. The classic register lives with distributors and curators. MUBI runs **Tiempos Headline/Text with LL Riforma** ([mubi.com](https://mubi.com)), chosen for "elegance, sophistication and sharpness" ([Fonts In Use: MUBI identity](https://fontsinuse.com/uses/51030/mubi-identity)). Janus Films pairs Freight Text with Freight Neo ([janusfilms.com](https://www.janusfilms.com)), Focus Features sets Palatino against Work Sans ([focusfeatures.com](https://www.focusfeatures.com)), and Cosmo Street Editorial uses Freight Display as a serif accent over Larsseit ([cosmostreet.com](https://www.cosmostreet.com)). The pattern is consistent: **a serif for headlines and editorial copy, a neutral sans for UI, and never serif everywhere**. Designer portfolios show the same thing, with Canela, Schnyder, GT Super and Ogg over Graphik, Founders Grotesk and Aktiv Grotesk ([Typewolf: Top 40 portfolio sites 2026](https://www.typewolf.com/portfolio-sites)). 2026 trend writing describes a serif revival in exactly this "serif headline over clean sans" form ([AND Academy: typography trends 2026](https://www.andacademy.com/resources/blog/graphic-design/typography-trends/)). Fontfabric's note that "sans-serif type is still the reigning champion" confirms the sans should still carry the reading load ([Fontfabric](https://www.fontfabric.com/blog/top-typography-trends-for-2026/)).

Pairing succeeds on structure more than category. Google's pairing guidance stresses similar x-height, contrast and width between partners ([Google Fonts Knowledge: Pairing typefaces](https://fonts.google.com/knowledge/choosing_type/pairing_typefaces)). Butterick's shortcut is faces by the same designer ([Practical Typography: Mixing fonts](https://practicaltypography.com/mixing-fonts.html)). That puts a free Tiempos stand-in beside a free Riforma stand-in, with matched x-heights, at the centre of the decision.

## Newsreader beats Instrument Serif because it can carry a whole hierarchy

The serif has to work from a 96px hero down to an 18px pull quote, so the deciding feature is a **real weight range plus an optical-size axis**. Newsreader was commissioned by Google Fonts from Production Type for on-screen reading. Its optical sizes change the design: at display sizes it is "more elegant with delicate and contrasting strokes, and a larger x-height", and at text sizes it has lower contrast ([Production Type: Newsreader](https://productiontype.com/font/newsreader)). On Google Fonts it ships **wght 200–800 and opsz 6–72 with italics**, and it is loadable by the repo's installed `next@16.3.6` (next/font `font-data.json`). It is the closest free analogue to MUBI's Tiempos. It is also uncommon (Google Fonts popularity rank 119), so it avoids the template look of **Playfair Display** (rank 22), which is widely described as overused ([Made Good Designs](https://madegooddesigns.com/playfair-display-font/)).

The already-loaded **Instrument Serif** fails as the system serif. It is **400 only**, a condensed display face ([Beautiful Web Type](https://www.beautifulwebtype.com/instrument-serif/)), so any heading at the site's current 650–800 weights would be faux-bolded. Browsers synthesise missing weights by "smearing" glyphs, which Stearns calls "an awkward mimicry of real type design" ([A List Apart: Say No to Faux Bold](https://alistapart.com/article/say-no-to-faux-bold/)). **Fraunces** has the range but a 1970s soft-serif flavour inspired by Windsor, Souvenir and Cooper ([Fraunces GitHub](https://github.com/undercasetype/Fraunces)), which reads trendy rather than classic. **Cormorant** and **EB Garamond** are beautiful large, but their x-heights (0.386 and 0.400) look undersized beside any modern sans below about 18px.

For the sans, **Hanken Grotesk** is the quiet grotesque that matches. Its x-height of 0.493 sits near Newsreader's 0.426 text master (capsize metrics shipped with Next), closer than Inter's 0.546. It is variable 100–900 with italics and is uncommon (rank 142). The research maps it, alongside Inter Tight, to MUBI's Riforma. **Inter** is the obvious fallback, with maximal small-size legibility, but it is the fourth most-used family on Google Fonts. **DM Sans** is technically sound, but it derives from Poppins, a geometric face ([googlefonts/dm-fonts](https://github.com/googlefonts/dm-fonts)), and film-site practice puts rounded geometric faces in the startup/template column. **Space Grotesk** has no italic and is the other half of the dev pairing, so it should go. One caveat: the Hanken–Newsreader pairing comes from metric and stylistic reasoning, not a published pairing, so it should be eyeball-tested before it is locked in.

## Two families plus a static mono cut font weight by roughly half

The current setup preloads **about 143 KB of latin WOFF2 across 5 files on every route**. Of that, **about 43 KB is Instrument Serif rendering zero text**, since `--f-serif` has no consumer anywhere in `src/` (measured against the Google Fonts CSS2 API; [Next.js Font API reference](https://nextjs.org/docs/app/api-reference/components/font) confirms root-layout fonts preload on all routes). The HTTP Archive puts the median font file at about 35–36 KB ([Web Almanac 2025: Fonts](https://almanac.httparchive.org/en/2025/fonts)). Cutting JetBrains Mono from its 40 KB variable file to a **21 KB static 400** is enough for timecode, and it can drop out of preload if no timecode sits in the first viewport. The Newsreader and Hanken payloads were not measured. Expect the variable serif with `opsz` plus italic to be the single largest item. The DM Sans measurement shows the cost of an extra axis: adding `opsz` raised its file from 37 KB to 63 KB. Next.js recommends variable fonts "for the best performance and flexibility" but loads only `wght` unless `axes` is set ([Next.js Font API reference](https://nextjs.org/docs/app/api-reference/components/font)). **Newsreader must be loaded with `axes: ['opsz']`**, or its main advantage is silently lost. That is the one extra axis worth paying for.

Weights need the same discipline. The CSS asks for **400, 500, 600, 620, 650, 700, 750 and 800**, with 62 rules at 650 or above. Butterick advises limiting heading levels to "three. Two is better" and growing size only modestly ([Practical Typography: Headings](https://practicaltypography.com/headings.html)). A classic serif display looks right at regular or medium, not 800. Collapse the sans to **400/500/600** and the serif to **400/500**, and let size and space carry the hierarchy.

## Recommendation

**Primary: Newsreader + Hanken Grotesk + rationed JetBrains Mono**

| Role | Family | Load (`next/font/google`) | Weights used | Where |
|---|---|---|---|---|
| `--f-display` | Newsreader | variable, `axes: ['opsz']`, `style: ['normal','italic']` | 400 (headings), 500 (h1/hero if needed); italic 400 | Hero name/lines, section headings, the `<em>` heading accents (Hero, Contact, Drawing Room teaser), praise/testimonial quotes, work-item titles |
| `--f-body` | Hanken Grotesk | variable (wght default), normal only | 400 body, 500 nav/buttons, 600 labels | Body copy, nav, buttons, forms, eyebrows and section labels (uppercase, `letter-spacing: 0.06–0.1em`, 12–13px), client names, captions, Studio UI |
| `--f-mono` | JetBrains Mono | static `weight: '400'`, `preload: false` unless above the fold | 400 only | **Only** timecode (HH:MM:SS:FF), durations, frame rates, version/date stamps, and Studio code-like fields (slugs, JSON/URLs). Target under about 10% of font references |

Body text uses 17–18px (clamping down to about 16px on mobile), line-height 1.5–1.6, and a measure of about 65ch. Display uses line-height 1.05–1.15 and 0 to −0.01em tracking at the largest sizes, in line with WCAG's 80-character and 1.5 line-spacing guidance ([W3C: SC 1.4.8](https://www.w3.org/WAI/WCAG22/Understanding/visual-presentation.html)).

**Alternative: Source Serif 4 + Source Sans 3 + Source Code Pro.** This is the maximum-uniformity route. It is the only superfamily on Google Fonts that is variable in all three roles, and the serif was drawn as "a complementary design to the Source Sans family" with shared proportions and colour ([Wikipedia: Source Serif](https://en.wikipedia.org/wiki/Source_Serif)). Load Source Serif 4 with `axes: ['opsz']` (8–60). Mono rules stay the same. The trade-off is less film-editorial personality: it reads institutional and neutral where Newsreader reads MUBI.

Rejected: keeping Instrument Serif (single weight, so it cannot carry headings), Playfair Display (overused), and the current Space Grotesk + JetBrains Mono voice (reads as a developer product).

### Implementation notes for this codebase

1. **`src/app/layout.tsx`**: replace the four imports with `Newsreader`, `Hanken_Grotesk` and `JetBrains_Mono`. Keep the variable names `--f-display`, `--f-body` and `--f-mono` so existing CSS keeps working. Delete the `Instrument_Serif` block and `--f-serif` (it has zero consumers). On the mono, set `weight: '400'` and `fallback: ['ui-monospace', 'SFMono-Regular', 'Menlo', 'Consolas', 'monospace']`. next/font otherwise metric-matches mono against Arial, so timecode would briefly render proportional before the font swaps in.
2. **The real work is the mono audit**: go through the 106 `var(--f-mono)` sites in `src/styles/base.css` and `src/styles/studio-inspector.css`. Re-point labels, eyebrows, nav and buttons to `var(--f-body)`. Keep mono only on timecode, duration and version selectors. Where mono was used for alignment, use `font-variant-numeric: tabular-nums` on the body face instead. Hanken Grotesk's tabular-figure support was not verified, so check it.
3. **Weights**: normalise the 620/650/750/800 values to the token set (sans 400/500/600, serif 400/500). Set explicit `font-weight` on `h1`–`h6`, since the browser default is bold. Add `font-synthesis: none` on `:root` once every used weight and style is actually loaded. Hanken is loaded without italic, so any `<em>`/`<i>` in body-face text (for example `WorkConsole` subtitles and `DrawingRoomTeaser` notes) either moves to the display face or needs Hanken's italic loaded.
4. **Caching on the Worker**: add `public/_headers` with `/_next/static/*  Cache-Control: public,max-age=31536000,immutable`. OpenNext serves static assets with `max-age=0, must-revalidate` by default ([OpenNext Cloudflare: Caching](https://opennext.js.org/cloudflare/caching)). This costs no Worker CPU and stays within the `(public)` rules in AGENTS.md.
5. **Verify**: run `pnpm check`. Build output needs network access to Google Fonts, and a production build fails without it. Compare payload with `ls -l .next/static/media/*.woff2` before and after. Check `/`, `/room` and `/resume` at mobile and desktop widths for heading wrap and CLS, since serif headings will reflow differently from Space Grotesk. Record the decision in `MEMORY.md`, which currently names the old fonts.

## Conclusion

The font choice matters less than the role discipline. Swapping families while leaving mono on about 100 selectors would give a serif-headed site that still talks like a terminal. What makes this system classic is that mono shrinks from the site's voice to a single domain-specific signal. Timecode is something only an editor's portfolio can use credibly, so rationing it turns a generic tech tic into a professional cue. The same move also removes the one family that renders nothing today, and makes the brand name `madhu.edit` read as an editor's mark rather than a filename.

The uncertainties are real and bounded. No perception study ties family count or mono share to "professionalism". The Newsreader + Hanken pairing is reasoned from metrics and film-industry analogues rather than a published pairing. The new payload is unmeasured. All three are settled in an afternoon with a branch, a build and a side-by-side at two widths, which is cheaper than debating them further.
